# 03 · 手写新脚本的分镜细化

**版本：S03_STORYBOARD v0.3 · 2026-10-18 · 分镜文本，尚未生成新素材或修改动画。**

依据[03当前正文](../../../../../scripts/final/shot/03.md)中的三条手写方案，顺序为雇佣关系 → 实际工作故事 → 树状关系。保留原127字符口播、原9条字幕正文与39秒预算；旧睡眠／唤醒、即时／集中验收对照、协商转次日等情节退出本轮方案。手写原文留存于[输入原稿](03-user-before.md)。

## 画幅、动作与文字约定

1920×1080，30fps，本章[0,1170)帧，全片[2490,3660)帧。日间公司办公室，延续灰蓝、暖木、暖白局部浮层；人物为完整位图绘稿，工资／工时流、消息、时间标记和树线是独立矢量。字幕固定在y994–1062，镜头变换不带动字幕。

开头逻辑0–9.1秒，故事9.1–30.5秒，结尾逻辑30.5–39秒；共11镜，故事21.4秒／逻辑17.6秒。沿原字幕入点排演出，尤其13秒出现雇主追加、25.7秒继续输入、30.5秒抽出决定权关系；这些是无配音暂排，不宣称已对轴。V03.1／2／3的0–13／13–27／27–39父段不改，一镜可以跨父段。

画面沿用手稿中的短文字：关系层“雇主／雇员／薪水／约定工时”；消息“工作已完成”，回复采用原例“17:00前准备一个会议报告”。这些是画面文字，不进入口播或字幕。不给雇主添加“辛苦了”等新台词，不增加薪资数额、罚款、绩效或劳动合同条款。人物身份以头像承担，角色名只在首次需要区分时出现。

## 分层、方向与动作执行

故事段的阅读顺序为清单完成 → 本人发送 → 雇主派发 → 本人看时间 → 本人看同事 → 回到输入。消息先发生、人物随后反应；不让背景同事、通知和主角同时做最强动作。右上消息窗不会遮主角左侧脸、手或底部字幕，发送与回复持续存在于同一会话，不用多个全屏UI顺序替代。

公司场景采用背景／桌椅／屏幕内容／完整人物／显示器与桌沿前景遮挡／消息／字幕的深度关系，实际近远顺序按每个机位的遮挡面确定。空办公室图中的桌子、显示器和椅背已经画在背景里；不能再平铺01整张工位导致重复桌面。可用同源裁切建立前景遮挡，反打或新视点须配对应空间底图。

程序员、钟面、邻桌位于同一空间：先明确他位于近侧工位，邻桌在画面右方；看同事的转头方向、主观镜头向右移动和切回目光方向一致，不镜像翻转人物或带字屏幕。焦点从消息到脸、从脸到钟、从脸到同事都有视线依据。短时模糊仅用于姿态动作点，消息、钟面和图解标签保持清晰。

树图中的工时格沿用开头约定工时对象S03-hours，工资符号S03-wage不在末尾变成工时或任务；消息联系人和上层节点均为同一S03-employer。末段关系解释限定在这个工时情境，不把树的上下位置画成人格高低，也不加入束缚人身的锁链或提线。
