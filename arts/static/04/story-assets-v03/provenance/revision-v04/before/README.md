## 构图与可编辑内容

- 三窗各608×912，接近全屏并始终同屏；主角／同事A／同事B各有独立完整场景态。窗口标签、执行反馈与来源为独立图层，不往笔记本背壳上贴UI。
- 绩效双窗各924×924，工作／反馈两态；字母与表情分开触发。两侧不是同一个主角换衣复制。
- 企业竞争保持一个共同市场，甲／乙／丙颜色和位置固定，四态对应同为1年、甲缩至3个月、乙丙普及、乙再缩至1个月。内部扇区权重仅用于假设动画状态，不是统计数据，不显示编造百分比；每态总量为1。
- 白板文字严格为“3人负责产品线”与“1人负责产品线”。保留预备、划除接触、下行改写接触和结果四态；接触态只显露笔尖附近已写部分，避免笔仍在起点而整行瞬间完成。完整写字运动与中间动作需在动画阶段制作。
- HR左侧688px、右侧招聘窗1174px。岗位始终为S04-JOB-01，选中旧要求→修改→发布→简历由少到多。画面提案“参与产品线开发”→“独立负责产品线／熟练调度多个Agent”已在分镜登记，不加入口播；匿名简历列表不包含真实个人资料。
- 底部997–1062px为字幕安全区；来源角标在960–992px，不重叠。阶段标签与证据类别沿分镜区分，不把绩效、周期或招聘情境冒充H1测量结果。

**动画接入请导入[assets.mjs](assets.mjs)的ASSETS／LAYOUT／scene及[画面文字单源](screen-copy.json)。** `scene(name, hrefs, state)`输出保留`data-layer`的SVG层；人物、主要道具和建筑引用PNG，文字与图表为原生可编辑图形。`compositions/*.png`只是栅格检查图，不作为平铺动画的唯一输入。并行窗内的整幅绘稿用于锁定接触透视，后续镜头运动可分别控制窗、UI与场景；不把人物拆成SVG肢体。
