**版本：** STORY_LOGIC_PLAN v0.2 · 2026-10-18。阶段：画面剧本及并行构图修订；首批故事美术已备，尚未接入章节动画。

本轮保留SHOT_TEXT v0.4的六章口播、来源和280秒预算。02–06以各章video content为当前画面需求（02为v0.3，03／04为v0.2，05／06沿用v0.1）；现有统一预览仍显示此前的基础图解版，不能据其技术检查宣称本轮故事场景已经制作。

## 两种画面的判定

**故事场景（E）：** 观众主要在看某个人，在具体地点、时段与情境下做什么，以及行动带来什么结果。主体是人物、空间、物件、表情与行动，例如夹菜时又伸手操作电脑、会前打开新任务、离席前收到排期。屏幕可以存在，但不以大图表承担主要叙述。

**逻辑展示（L）：** 观众主要在理解对象之间的关系、概念区分、条件变化、互斥方案或证据范围。头像搬运文件、节点反馈、时间带和任务数量比较属于此类；图解旁的装饰人物小窗不改变主叙述职责。人物在真实空间里行动、主副窗共同表现触发与反应，或三个人物场景并置时，仍可属于E；不能按窗口尺寸判定E／L。研究定位和文献卡作为“逻辑展示／证据与来源”单独标明，不冒充故事。

每段只选一个主要类型；故事场景中必要的来源角标或短UI，不使它变成逻辑展示。需要解释抽象机制时，另划一个有入点、出点的L段，而不是在整段图表后面循环播放敲键盘。两类按叙事交织，不先播放全部故事再集中讲理论。

## 04三画幅并行场景与03主副窗

04的4–15秒合为V04.1-E1并行场景组：午餐／会前／晚间三个实际故事画幅始终同屏，分别表现用餐转向电脑、等候时开任务、晚间重新打开电脑。动作重音可随口播依次落在一窗，其他两窗仍在场；不是三次顺序切换，也不是现实同一时刻。每窗有可见空间、人物与接触动作，Agent状态层贴近该窗，不用三个标题框／头像替代场景。

03通知打断休息采用主画面程序员伏桌睡眠→醒来，右上通知窗独立入场；公司工作日内短暂休息的说明情境不推成普遍夜间待命。02／03负责人追加任务也可用行动小窗与程序员主画面并行，先递交／排期、再引发注意与接收，保留因果延迟。窗口并行不要求所有动作同时启动。

首批[故事美术与代表构图](../../../arts/static/story-assets-v01/README.md)已备；这些仍是研究主题的卡通说明情境，不是受访者、真实访谈或逐字事件复原。必要单一公司限定在正式入场保留一次，避免重复解释段落。

## 故事与逻辑如何交接

| 接点 | 画面交接 |
|---|---|
| 01→02 | 01未排期的feedback卡，匹配切入电脑里同标记的搁置需求；人物先查看，随后才抽出成本收益筛选关系。已排期、已验收及已合并任务不重置。 |
| 02→03 | 02结束在人物仍处理任务的工位；03另起明确的工时说明情境，用同一查看动作接入新的S03任务集，随后把空清单与仍在走的工作时段并置。 |
| 03→04 | 团队实际排期页成为研究定位的画面入口；研究卡之后切到餐桌、会前和晚间。04情境不冒充03人物的真实田野经历。 |
| 04→05 | 额外测试被负责人勾进常规验收，最后抽出“周期／标准”；05从人物收到该安排、调度工具开始，再展开组织决定权。 |
| 05→06 | 05在“谁参与决定”的规则节点留下入口；06匹配到共同讨论的排期页，比较两种配置后，实际演出参与与生活结果。 |
| 06回扣01 | 以回看交代个人时间开始之前的收工节点，回到开场同一工位／机位和任务线的新一轮交付T06-final；原T01仍已通过，不再次清零。经人验收并按约定收工，后台继续与人的离开可同时成立；不能将此剪成生活时间又被工作打断。 |

E↔L转换必须携带对象：任务页→任务卡，排期格→时间带，验收勾→标准节点；返回故事时落到同一物件和人物行动。不得把工作终点直接改叫成本阈值，或把定性人工投入条直接改叫约定工时。
