## 工作顺序与交付

| 阶段 | 输入 | 产物与验证 |
|---|---|---|
| 内容审核与压缩 | 六章工作文本、来源说明、课程要求 | 正常语速下可落入 3～5 分钟的审核稿；记录确认依据 |
| 临时配音与对轴 | 审核稿、确定的临时声音 | 句子级时间轴与字幕；记录实测时长，抽听句子边界 |
| 角色与故事设计 | 审核稿、ART_DIRECTION、识别度参考 | 角色视图和部件、背景与道具图层、关键姿态与动作链 |
| 逻辑与镜头设计 | 故事道具、时间轴、各章概念与来源 | 逻辑对象和动态关系；含构图、动作、起止状态和接续对象的子镜头说明 |
| 代表镜头预览 | V01.1角色片段、V02.2故事转图解片段 | Claude编写分层场景，检查角色识别、遮挡、互斥方案、读图与声画衔接，回写统一样式 |
| 分章实现 | 样片通过的组件与同一套参数 | 六章共用组件、样式与时间轴；逐章审阅 |
| 正式声音与导出 | 审核场景、正式配音、字幕与文献页 | 总时长 3～5 分钟的成片、依赖锁、命令和校验值 |

## 给 Claude 的输入约定

每次提供明确版本的 audio content、video content、句子时间轴（尚未实测时标明暂定）与 STYLE_BIBLE，注明待审状态。使用 `storyboard-prompt-assistant` 做文字分镜；使用 Remotion 官方 skills 编写、预览和渲染动画。

分镜至少含：章/场景 ID、对应旁白、时间区间、背景/人物/道具/逻辑/字幕图层、构图锚点、起始状态、动作触发、状态变化、来源、屏幕文字、声音与终止衔接。先完成角色、故事与逻辑设计，再把现有video content细化成可执行子镜头。配音只读 `<start>` / `<end>` 内的 audio content；字幕再按 references 添加脚注。对于代码动画，以组件行为和时间变化表达画面，不强制写文生视频的负面提示词、种子或平台专属参数。

## 实现约定

- 图解容器默认透明，依内容边界、字号和人物避让区布局，不预设所有图解占满画幅。不要默认挂载logic-panel或全屏遮罩；必要的对比处理优先局限在文字或实际内容附近。

- 用 React / Remotion 管理场景、时间轴与渲染；SVG、Canvas 等只在需要时作为工程内元素。
- 在同一处维护色板、字体、布局、字幕与转场参数；它们对应同一 STYLE_BIBLE 版本。
- 用句子 ID 关联旁白与场景，避免不同章各自重写时间数据。
- 可复用任务线、时间带、排期卡、证据卡和对照框；所有数字和来源文字必须能回链。
- 字体、音频、引用与其他素材记录来源和版本；当前 `assets/references/` 图片未获选用。
- 预览先验证字号、对比度、字幕安全区和核心机制，再在收到具体导出任务时渲染视频。
- 正式输出须绑定正文、分镜、风格、声音、代码版本与依赖锁，详见 [制作协议](PRODUCTION_PROTOCOL.md)。

内容取舍、来源与风格的采用须留下审核依据；Claude 的生成完成声明不能替代这些记录。完整提示词、输入输出和渲染信息写入 [生成日志](../doc/GENERATION_LOG.md)。
