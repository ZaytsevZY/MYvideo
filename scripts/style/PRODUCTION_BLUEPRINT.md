# 《Agent 在工作，人真的下班了吗？》制作蓝图

**状态：** 计划稿 v0.1，待审核；不构成正式分镜、脚本或素材生成授权。  
**目标：** 用“回形针式讲解”表达论证，用“pdoom 式统一视觉系统与可控代码渲染”保证一致性；旁白而非音乐决定时间轴。

## 0. 不变的工作顺序

```text
OUTLINE v1.0
  → SCRIPT v1.0 + 临时配音
  → treatment / STYLE_BIBLE / 句子级时间轴
  → 15 秒样片
  → 正式场景与素材
  → 粗剪、事实复核、终配与导出
```

当前只允许完成第一项的核验与冻结。没有 `SCRIPT v1.0`，不得开始正式分镜、画面生成或编码实现。

## 1. 影片的解释逻辑

### 一句话目标

观众应理解：Agent 可以让人离开执行步骤，却不自动让人离开持续增加的工作要求；“是否下班”还取决于谁决定任务量、响应义务与完成标准。

### 六段旁白与画面任务

| 段落 | 时间 | 旁白的工作 | 画面必须解释什么 | 当前需核验 |
|---|---:|---|---|---|
| 1. 开场 | 0:00–0:22 | 建立“睡前派活、机器继续工作”的具体情境，提出问题。 | 人短暂输入与机器长时间执行的差别。 | 这是说明性情境，不包装为实测。 |
| 2. 理论问题 | 0:22–0:57 | 用一条马克思思想说明：节约劳动不等于自动缩短工作。 | 同一条“节约出的能力”可通向自由时间或再投入生产。 | 中文译文、版次、页码和口播措辞。 |
| 3. Agent 条件 | 0:57–1:33 | 解释一次指令如何启动持续、异步、一定程度自主的执行。 | 三种时间：人操作、机器运行、人的可支配时间。 | Agent 表述是否准确、不过度承诺。 |
| 4. 转化机制 | 1:33–2:42 | 解释“我多做一点”怎样可能变为“人人应做到”。 | 额外交付 → 排期/评价变化 → 正常任务量重设。 | Haas 研究的范围和说明性案例的标注。 |
| 5. 重新理解下班 | 2:42–3:13 | 回到个人体验，说明离开电脑不必然离开工作要求。 | 任务数量、响应义务、产出标准如何侵入可支配时间。 | 不把机器后台运行等同人的劳动。 |
| 6. 结论 | 3:13–3:40 | 给出判断而非“技术有利有弊”。 | 机器持续执行 ≠ 人必须持续进入工作。 | 收束句与前文是否完全闭环。 |

## 2. 视觉系统：借鉴原则，不复制参考片

### 视觉语言

- **类型：** 理性、平静、高信息密度的解释性动画；不是音乐 MV，不用炫技替代推理。
- **统一性：** 一套色板、字体、网格、标注规则、转场逻辑和“任务线”母题贯穿全片。
- **节奏：** 以句子起止、重音、转折词和停顿为时间锚点；不按鼓点，也不为每句制造新场景。
- **具象限制：** “程序员与 Agent”只作为贯穿情境。其余画面以任务流、时间线、排期、证据卡和对照结构讲清机制。
- **禁止项：** 赛博霓虹、发光大脑、代码雨、泛用机器人、堆砌写实 AI 人物、无信息的漂浮粒子、未经授权的产品 UI 或艺术风格模仿。

### 待 `SCRIPT v1.0` 后冻结的视觉母题

| 母题 | 语义 | 复用位置 |
|---|---|---|
| 任务线 | 一条从人的指令出发、穿过 Agent 流程的细线。 | 开场、第三段、第四段、结尾。 |
| 三层时间带 | 人的操作 / 机器执行 / 可支配时间三条平行时间带。 | 第三、五段。 |
| 排期卡片 | 同一团队计划表由“额外交付”逐渐压缩为常规期限。 | 第四段。 |
| 证据卡 | 来源、对象、观察到的事实、不能推出的结论。 | 第二、四段与片尾。 |
| 对照框 | 左右两种可能：释放时间 / 重设要求。 | 第二、五、六段。 |

## 3. 可复用资产与记录要求

| 资产 | 是否复用 | 应记录什么 | 最低验收 |
|---|---|---|---|
| 色板、字体、网格、字幕安全区 | 全片复用 | 版本、字体来源/授权、色值、尺寸规则。 | 任一场景可按规则重建。 |
| 任务线、时间带、排期卡、证据卡、对照框 | 跨段复用 | 组件名、输入参数、示例、代码路径。 | 换文字/数据即可复用，无须重画。 |
| 旁白时间轴 | 全片唯一来源 | 脚本版本、录音版本、每句起止、停顿、重音、对应来源。 | 画面可由句子 ID 对齐而非硬编码秒数。 |
| 图表/来源数据 | 只在相应段复用 | 原始链接、下载日期、转换方法、许可和最终显示文本。 | 每个数字可回到原始来源。 |
| AI 生成素材（如最终需要） | 严格受控 | 完整提示词、模型/版本、参数、参考输入、输出哈希、审核结论。 | 能说明它服务哪句旁白、为何被选用。 |
| 代码和渲染 | 全片复用 | 提交号、依赖锁定、渲染命令、分辨率、帧率、编码参数。 | 本机可重复导出同一版本。 |

## 4. Claude 与人的责任边界

### 适合交给 Claude 的任务

1. 将已冻结的旁白拆为句子级时间轴、字幕与场景数据结构。
2. 从已批准的视觉规则生成 SVG / Canvas / Three.js 组件和确定性动画代码。
3. 将“任务流、三层时间、排期变化、证据卡”实现为可传参模块。
4. 生成预览、联系表、字幕文件、渲染脚本与技术自检工具。
5. 根据已给来源撰写屏幕短注；只做压缩与排版，不自行补造事实或引文。

### 必须由人审核或决定的任务

1. 中心判断、理论解释、任何研究结论与正式引文。
2. 哪一句值得停顿、画面是否真正帮助理解，而非只是“好看”。
3. 每个证据卡的显示范围、来源与适用边界。
4. 风格圣经、正式镜头列表、AI 素材是否进入成片。
5. 每次生成/渲染的最终采用与淘汰决定。

### 不应交给 Claude 自行决定的事项

- 不让 Claude 从未核验材料中自行寻找“数据支撑”。
- 不让 Claude 在无风格圣经时批量生成镜头或素材。
- 不让 Claude 用新画面替代尚未写清的因果推理。
- 不让 Claude 推断版权、引用许可或研究结论的适用范围。

## 5. 给 Claude 的委托包

每次委托只给一个冻结版本与一个明确产物，避免“做整片视频”的模糊请求。

### 委托包 A：旁白时间轴（脚本冻结后）

**输入：** `SCRIPT v1.0`、临时配音 WAV、来源注释。  
**产物：** `narration.json`（句子 ID、起止时间、重音、停顿、段落、来源 ID）与 SRT 字幕。  
**验收：** 无改写事实；每句可回链脚本；时间与音频抽查一致。

### 委托包 B：视觉系统原型

**输入：** `STYLE_BIBLE v1.0`、一个段落的解释任务、旁白时间轴片段。  
**产物：** 可预览的单场景代码和一张联系表。  
**验收：** 只使用批准色板/字体/母题；不出现禁止项；能由参数替换文本或数据。

### 委托包 C：15 秒机制样片

**输入：** 第四段中已锁定的 15 秒旁白、排期卡与任务线规则。  
**产物：** 1080p 预览、渲染命令、逐项自检表。  
**验收：** 不靠旁白也能看出“额外交付 → 排期压缩 → 新标准”；与旁白节奏同步；资料来源可见且不遮挡。

## 6. 你接下来要做什么

### 现在：内容审核，不做视觉

1. 核验并确认第二段使用的马克思中文引文。
2. 核验并确认 Haas 研究在第四段可使用的准确表述。
3. 审核六段时长和中心判断；批准后冻结 `OUTLINE v1.0`。

### 大纲冻结后：脚本与声音

1. 先写第四段 260～290 字完整口播。
2. 写开场和结尾，再完成约 820～920 字全稿。
3. 用正常语速录一版临时配音；不要等最终配音才校时。
4. 依据临时配音形成 `SCRIPT v1.0` 与句子级时间轴。

### 脚本冻结后：只做一个样片

1. 制定 `STYLE_BIBLE v1.0`，冻结视觉母题和禁止项。
2. 以第四段的因果链做 15 秒 1080p / 30fps 样片。
3. 审核“信息能否被看懂、风格是否一致、旁白是否有呼吸空间”。
4. 样片通过后，再向 Claude 分段委托可复用组件与正式场景。

## 7. 完成定义

这支片子完成，不是“有许多 AI 画面”，而是：

- 任一关键判断都能回到旁白和来源；
- 任一画面都能说清它解释哪一句；
- 同一视觉系统贯穿全片；
- 人的直接操作、机器运行和可支配时间没有混为一谈；
- 正式素材、代码和渲染均有可追溯记录；
- 一位未参与者看完后能复述“额外能力如何可能变成正常要求”。
