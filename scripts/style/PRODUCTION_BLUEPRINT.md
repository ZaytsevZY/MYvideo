## 已确定的路线与当前状态

用户已明确：由 Claude 编写动画代码，再渲染成片；以 Remotion / React 为实现路线。计划使用 Claude Opus 5.5，实际模型、工具、依赖版本在执行时登记。本轮仅整理文件，尚未建立 Remotion 工程或进行新渲染。

当前内容为待审核的六章工作文本，风格为候选 STYLE_BIBLE v0.1。旧 Python / Pillow demo 不是当前工程，不直接继承其时间轴、声音或渲染状态。

## 工作顺序与交付

| 阶段 | 输入 | 产物与验证 |
|---|---|---|
| 内容审核与压缩 | 六章工作文本、来源说明、课程要求 | 正常语速下可落入 3～5 分钟的审核稿；记录确认依据 |
| 临时配音与对轴 | 审核稿、确定的临时声音 | 句子级时间轴与字幕；记录实测时长，抽听句子边界 |
| 分镜与风格确认 | 审核稿、时间轴、候选 STYLE_BIBLE | 分镜表、明确的样式参数与审核记录 |
| 代码机制样片 | 一段约 10～15 秒旁白、分镜与风格 | Claude 编写 Remotion 场景，预览并检查解释性与声画同步 |
| 分章实现 | 样片通过的组件与同一套参数 | 六章共用组件、样式与时间轴；逐章审阅 |
| 正式声音与导出 | 审核场景、正式配音、字幕与文献页 | 总时长 3～5 分钟的成片、依赖锁、命令和校验值 |

## 给 Claude 的输入约定

每次提供明确版本的正文、句子时间轴、分镜与 STYLE_BIBLE，注明待审状态。使用 `storyboard-prompt-assistant` 做文字分镜；使用 Remotion 官方 skills 编写、预览和渲染动画。

分镜至少含：章/场景 ID、对应旁白、时间区间、画面元素、状态变化、屏幕文字、声音与衔接。对于代码动画，以组件行为和时间变化表达画面，不强制写文生视频的负面提示词、种子或平台专属参数。

## 实现约定

- 用 React / Remotion 管理场景、时间轴与渲染；SVG、Canvas 等只在需要时作为工程内元素。
- 在同一处维护色板、字体、布局、字幕与转场参数；它们对应同一 STYLE_BIBLE 版本。
- 用句子 ID 关联旁白与场景，避免不同章各自重写时间数据。
- 可复用任务线、时间带、排期卡、证据卡和对照框；所有数字和来源文字必须能回链。
- 字体、音频、引用与其他素材记录来源和版本；当前 `assets/references/` 图片未获选用。
- 预览先验证字号、对比度、字幕安全区和核心机制，再在收到具体导出任务时渲染视频。
- 正式输出须绑定正文、分镜、风格、声音、代码版本与依赖锁，详见 [制作协议](PRODUCTION_PROTOCOL.md)。

内容取舍、来源与风格的采用须留下审核依据；Claude 的生成完成声明不能替代这些记录。完整提示词、输入输出和渲染信息写入 [生成日志](../doc/GENERATION_LOG.md)。
