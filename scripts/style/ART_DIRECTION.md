**版本：** ART_DIRECTION v0.1 · 2026-10-15
**内容基准：** [SHOT_TEXT v0.4](../final/shot/README.md)，口播840个非空白字符，暂定4:40。
**状态：** 用户已明确叙事形式与识别度要求；以下角色造型、分层及镜头示例为设计草案。本轮未生成角色资产、建立工程或改写六章正文。

## 可行性判断与基本约束

可采用“人物行动 → 提取关系 → 动态解释 → 结果回到人物”的连续动画。故事线提供任务、处境和选择；逻辑线解释任务规模、时间配置、响应义务与决定权。两条线共享人物、任务和场景道具，不按章机械轮流播放故事与图表。

用户明确的约束：

- 不采用MV叙事：不以空镜、音乐卡点、整屏文字或纯氛围特效填充时长。夜转晨必须解释异步执行，人物离开必须解释人的操作结束。
- 不采用slide叙事：不以逐页独立图表承担全片。图解由既有物件展开，其变化有可见原因，结果能回到故事处境。
- 每段画面承担新增信息、空间关系或因果变化。高信息密度通过顺序组织实现，同一时刻突出一个主要关系。
- 允许读图和动作完成后的短暂停顿；停顿用于理解，不靠无意义运动填充。连贯性允许必要切镜，依据对象与行动衔接。
- 片尾文献与成员信息仍保留，属于出处交付；正文中的证据图采用动态定位和必要标签，不扩展成连续文献幻灯片。
- 角色以识别度为先，可参考已有模型拟人形象；画风可以简化，所有角色、场景与图形保持一致。

现有纯代码路线可从二维卡通、平涂和有限阴影开始。人物采用有限姿态、分部件关节和表情变化，暂不把高精度逐帧人体动画作为制作前提。参考图的完整细节复杂度需简化；人物侧面、手部遮挡与入座动作应先通过样片验证。

## Character：识别特征与可动画部件

已查看 [anime-contact1.jpg](../../assets/references/anime-contact1.jpg)：其人物设定含橙色短发、星芒装饰、浅色外套与深色内搭，以及正侧背视图和表情。此处依据用户提供的参考形象，不将其表述为已核验的官方角色设定。

| ID / 角色 | 候选视觉识别 | 动作和叙事职责 | 分层与一致性 |
|---|---|---|---|
| C-P / 程序员 | 深色短发、蓝灰上衣、固定工牌；性别不作为论证信息 | 派发、查看、退回、离席、休息、参与排期；沿用同一人贯穿六章 | 头、眼眉、躯干、上下臂、手、腿分件；头像直接复用头部组件 |
| C-A / Agent | 优先参考橙色短发、星芒发饰或胸标、浅色短外套、深色内搭；缩小时仍保留发型与星芒轮廓 | 接收目标、执行、报告结果、收到返工；多实例使用同一识别体系加编号 | 发型、脸、星芒、衣身、手臂分件；工具图标外置；全身与头像同源 |
| C-M / 企业负责人 | 与程序员相同的人体比例，较深外套、固定文件夹或排期笔；以道具和行为区分职责 | 接收需求、列入排期、调整交付标准；表情克制 | 不用夸张反派特征；涉及所有权时，图中另列企业产权与组织规则节点，不把所有管理者直接等同资本所有者 |

首轮角色交付应包括正面、3/4侧面、工作侧面，及中性、专注、疑问等少量表情；先完成派发、执行、审核、指向、离席和休息所需姿态。完整转身等高成本动作按实际分镜追加。

Agent 的拟人化用于让执行过程可追踪。它不能在剧情中自行决定企业工时或收益分配；新增要求须来自人物行动或组织规则。角色识别色与图表状态色分开：橙发用于辨认角色，不自动表示风险或新增任务。制作控制上，二维卡通为当前首选提案；像素风可作为统一替代方案，不在同一片中混用两套角色语言。

## Episode：分层场景与行动链

| 场景 | 可复用图层与锚点 | 能推进论证的行动 | 连接逻辑图的物件 |
|---|---|---|---|
| E-D / 开发桌面 | 远层窗景与日光、墙面；中层人物与Agent工作区；桌面、显示器遮挡；前层手与输入设备；屏幕独立遮罩 | 派发、离开、后台执行、验收、退回 | 同一任务卡、光标、人的操作带、机器执行带 |
| E-P / 团队排期 | 团队工作区、负责人、程序员、可编辑排期面板；保留屏幕或桌面上的原任务标记 | 搁置需求被加入计划，自选补充变成验收项 | 项目卡、截止线、验收标记、规则笔 |
| E-R / 工作与生活边界 | 同一人物、餐桌或居家阅读区、设备通知层；工作窗口与休息区域分开 | 集中验收保留连续时间，响应要求打断生活动作 | 响应窗口、时间区段、工作边界 |

图层需要明确前后遮挡、旋转中心、手与键盘接触点、人物视线目标、屏幕内容区域及昼夜光线。昼夜变化由窗光、照明与执行状态共同解释，不能只拍一个变亮的空房间。故事中每次重复任务应改变一个状态，避免用无变化的敲键盘循环充时。

## Logic：概念、机制与证据的不同画法

| 章 / 逻辑对象 | 来自故事的锚点 | 动态解释 | 边界 |
|---|---|---|---|
| 01 / 人与机器的时间 | 程序员离席、Agent接收同一任务 | 人的操作停止，机器轨继续；次日审核重新进入人轨 | 机器运行时长不合计成人的劳动 |
| 02 / 候选项目与两种分配 | 既有项目卡、节约出的人的投入区段 | 项目卡进入定性可行区；同一节约区段依次进入缩时或新增任务方案 | 可行不等于必定立项；不造收益百分比，不把成本轴当价值定义 |
| 03 / 工时与响应义务 | 已完成任务、尚未结束的约定时段 | 清单终点与工作时段终点分离；通知切断连续休息 | 有响应义务的时间与实际操作分别显示，不能把整个窗口一概涂成劳动时间 |
| 04 / 研究和标准变化 | 研究来源入口、同一张额外测试卡 | 样本范围定位；自选补充→下轮排期→常规验收 | 研究说明与作者情境分段标识，不伪造受访者、原始录像或实测曲线 |
| 05 / 调用权与决定权 | Agent接收指令、负责人编辑规则 | 调用路径畅通，排期和分配路径由另一组规则控制 | 箭头标明控制、流转或反馈，不能用一个箭头同时代替所有关系 |
| 06 / 时间去向与共同决策 | 同一角色、同一初始任务与边界线 | 改变决策参与和任务边界，展示对应生活时间 | 情境对照不宣称为已经发生的研究结果 |

Haas材料中的“约200人”描述公司规模；“八个月”描述观察期；“四十余次”描述半结构访谈次数。三项应以范围、时间、访谈三种图形表达，不画成共享数轴的柱状图，不把公司人数画成实际受访人数。没有工作强度百分比或时间序列数据时，只画带“机制示意”标记的关系变化。经典转述、研究观察、作者情境继续沿用现有尾注来源。

## Shot：从需求转为可执行画面

每个子镜头记录：`ID / 口播锚点 / 起始状态 / 背景与角色及道具图层 / 构图 / 动作触发 / 时间内变化 / 图解含义与来源 / 终止状态 / 接续对象`。

构图用画面比例或锚点表示；最终代码再统一映射到像素。短标签、数字和脚注单列为可编辑文字层；背景和角色不烘焙图表文字。头像应调用同一头部组件，无需从已渲染的整幅画面重新裁切。以下时间沿用当前预算，需配音后校准。

### 示例 A：V01.1 夜间派发与次日验收，0–16秒

| 时间 | 图层、动作与构图 | 新增信息与衔接 |
|---|---|---|
| 0–3秒 | C-P坐在画面左下的开发桌前；显示器位于中部，C-A在屏幕右侧工作区。窗景、人物、桌面遮挡和屏幕分别成层。C-P把尚未完成的任务卡从自己的输入区拖入C-A的接收槽。 | 建立人物、任务和派发关系；任务卡有持续可辨的图形标记 |
| 3–6秒 | C-A接收同一卡片，依次展开代码、测试、结果三个操作位置。C-P结束输入、移开手并离席；机位保持，工作区仍运行。 | 人的操作结束与机器继续执行同时可见 |
| 6–10秒 | 窗光由夜色转晨光；Agent的测试支路出现待修项，结果集合保留通过项与待检查项。 | 昼夜变化压缩等待过程；不是空镜，也不把执行动画等同可靠交付 |
| 10–16秒 | C-P回到原位置打开结果，核对后把待修项推回同一Agent接收槽。镜头向任务卡收拢，桌面边缘延展成下一段时间轨。 | 审核、返工和责任进入画面；任务卡保持身份，连接V01.2 |

### 示例 B：V02.2 同一节约区段的两种配置，章内13–27秒

构图提案：人物全身退到左侧，保留可辨头像；桌面沿水平方向展开为时间轴。中部是带同一标记的节约区段，上下分别为两个情境窗口。上方短标签“保持交付／缩短工时”，下方“增加任务／维持工时”；箭头表示分配方案，不代表两个已经同时发生的结果。

| 相对本段时间 | 具体动作 | 状态含义 |
|---|---|---|
| 0–2秒 | C-P收回操作的手，人物动作暂停供读图；同源头像移到时间轴左端。当前任务完成后空出的区段被框出，背景保留桌面轮廓。 | 从故事中提取讨论对象，标“方案示意” |
| 2–6秒 | 仅激活上方箭头；同一节约区段进入上方时间轨。上方子画面中，人物关闭工作窗口、进入阅读或休息动作。下方仅留灰色轮廓。 | 保持约定产出的缩时方案；可支配时间取决于相应边界安排 |
| 6–7秒 | 节约区段回到共同起点，上方转为带“方案A”标记的结果预览。 | 显示重置，不从上方结果再生成第二份节约 |
| 7–11秒 | 激活下方箭头；同一节约区段填入新增任务标记。下方子画面中，人物继续派发，C-A接收新任务。 | 扩大交付的另一种配置 |
| 11–14秒 | 两种结果以互斥方案并列，保留共同起点和一次节约的标记。下方新增任务卡放大，带入V02.3的任务数量解释。 | 对照读图；离开图表时保持任务对象连续 |

此处人物短暂暂停具有读图职责。单纯给两张静态图添加淡入、头像和箭头，仍不足以满足连续叙事要求；需要实际演示区段转移、方案重置与任务结果。

## 技术可行性与先行验证

建议由Claude编写分件SVG角色、可复用场景道具和动态SVG图解；复杂度优先放在解释关系与对象连续性。Remotion可用帧号驱动位置、透明度、旋转等属性，并用Sequence管理元素的出现时段；这些能力支持上述分层与变形方案，但不保证生成代码自动达到预期艺术质量。依据：[Animating properties](https://www.remotion.dev/docs/animating-properties)、[Sequence](https://www.remotion.dev/docs/sequence)（2026-10-15查阅）。

设计推进顺序为：角色设定与部件 → 故事场景和关键姿态 → 各章逻辑对象与来源 → 分层子镜头说明 → 代码预览。角色、图解和字幕共享样式入口；使用同一对象ID维持连续性，动作由帧号决定。

先验证两段代表片段：V01.1的16秒角色场景，以及V02.2的14秒故事转图解。前者检验角色识别、遮挡和验收动作，后者检验读图、互斥方案与回到故事的衔接。两段通过后再展开全片；本稿不宣称已有可运行样片。

主要风险是角色姿态过多、动作遮挡错误、图表和人物抢占注意，以及头像旁贴文字导致再次滑向slide。逐段检查观众能否指出“谁行动、什么改变、为什么改变”；不能回答时，应重写该段行动或关系，而非增加装饰。
