# 分章动画制作

把现有音画稿推进到可检查、可接续的动画章节。模型、工具与渲染框架按任务选择；本技能不要求Claude，不把01的45秒、12镜或素材数量复制为其他章的指标。

## 启动与恢复

1. 明确目标章、用户要求的阶段与交付范围。仅要求剧本或素材时完成对应阶段；要求完整制作时推进到所需交付，不把阶段拆分变成反复索要确认。调用本技能本身不授权一次生成02–06或额外制作声音。
2. 找到含 `scripts/PROJECT_STATE.md` 的仓库根目录。下述项目路径相对此根目录；技能内部链接相对本文件。
3. 读取 `scripts/PROJECT_STATE.md`、`scripts/HANDOFF.md`、目标及相邻章的 `scripts/final/shot/NN.md`，再查 `scripts/style/STYLE_BIBLE.md`、`scripts/style/ART_DIRECTION.md` 中相关规则。内容主张按该章尾注定位 `scripts/doc/SOURCES.md`，新增或存疑事实另行核验。
4. 检查目标章已有素材、布局、代码、字幕、导出与provenance，从已完成阶段继续，避免重复生成或覆盖历史。当前六章已接入 `arts/actions/film/README.md` 的统一展示；修改原章后重建film包，检查对应全片offset与接点。
5. 本次及此前有效用户要求优先。旧协议中的“必须Claude／Remotion”与现状不符时，按当前工具自由的要求执行并登记实际路线；生成完成或文件名中的final不代表用户冻结。

## 工作阶段

按需读取 [制作流程](references/workflow.md)；细化镜头前读取 [连续性与02–06接续](references/continuity.md)。

| 阶段 | 具体结果 |
|---|---|
| 剧本与镜头 | 先将画面分为故事场景E与逻辑展示L，写清主画面职责、口播锚点、动作与起止状态，再细化镜头；保留论证边界 |
| 美术资源 | 先复用库存，按真实构图列缺口；人物／头像／主要道具用统一画风完整绘稿，文字和反馈独立 |
| 代表构图 | 在目标画幅验证景别、透视、朝向、接触点、遮挡、文字与字幕避让后接入全段 |
| 动态演出 | 人物行动触发图解，对象变化解释逻辑；镜头、表情、动作反馈协同，避免立绘滑动与slide串联 |
| 字幕与声音 | 同版口播生成字幕；无配音时明确暂定排时，仅在用户要求时制作配音／音效 |
| 导出与交接 | 确定性逐帧导出，检查媒体、编码后画面与相邻章接缝，保存下一章可接收的状态 |

用 [章节制作单](assets/chapter-plan.md) 记录计划和实际结果；按任务删减无关栏目，不创建空目录充数。

## 从01继承的关键判断

剧本分类先读项目 `scripts/final/shot/STORY_LOGIC_PLAN.md`：E是人物在具体空间中的行动和结果，L是关系、机制、对照与证据；头像搬运或图表旁的装饰小窗仍算L；具体人物场景的并行分窗、主画面反应＋通知／组织行动小窗可以是E。按主叙述职责判断，不按窗口大小判断。新E所需素材不足时列缺口，不能直接降格成图表。

- 故事与逻辑相互推动：人物操作引出任务变化，图解结果回到人物处境。逻辑段可用头像选择、搬运与验收文件，配操作小窗，避免大段站立说理。
- 并行构图先按整幅定主次、视线与因果：通知小窗先触发，主画面人物随后反应；午餐／会前／晚间按当前用户要求三窗同屏，各窗独立行动，动作重音可依次推进。分窗不是三个时间轴时长相加，亦不暗示三个时段现实同时发生。
- 景别、角度、景深为信息和动作服务。情境段可用近景／越肩／反打；读图时文字稳定，不能靠全程推拉制造动感。新机位需要对应背景和完整姿态。
- 使用完整透明PNG人物与表情；不拼接肢体、拉伸身体或叠化两个身体。完整姿态表达预备、接触、过渡与收势；运动模糊短时用于动作，不影响必读信息。
- 人物、头像、工位、台灯、鼠标、电脑、纸张等主体优先复用或按需用图像模型重绘。简陋SVG转PNG不算重绘。共处一个透视的工位尽量整体准备，小窗复用同套资源。
- 文字、勾选、思考星芒、动作线、轨迹、遮罩及局部底框保留矢量。反馈贴近触发对象，思考标志随执行开始和停止，同一时刻突出一个主要信息变化。
- “生成结果”与“人工验收”分开；新任务进入计划要有人的选择或组织排期触发。区分人的操作、机器执行、可自主支配时间。定性示意不编造统计曲线。
- 精简装饰性解释，保留会改变论证含义的限定、证据类别与来源。04单一公司研究不能与机制示意共用实证标识。
- 字幕固定于屏幕空间，不随镜头和图解缩放；主画面不再复写整段口播。

## 工具与文件

- 可以直接完成写作和代码，不要求外部模型调用或登录测试。如用户选择Claude，沿用英文prompt、充分等待、避免频繁重试的偏好；先审校结果再决定是否重试。
- 需要生成或编辑位图时，使用当前可用imagegen技能／工具，先看参考图，按实际机位、光照和透明需求生成，不以SVG自绘冒充生图。
- 当前可运行参考是 `arts/actions/01/` 原生SVG／JavaScript逐帧合成，尚无Remotion工程。无需仅为导出迁移框架；实际采用Remotion时再读对应skills。不要只改文件名就运行写死01参数的脚本。
- 共用角色放 `arts/characters/`，章专用姿态／头像沿用其 `poses/NN/`、`portraits/NN/`。背景、道具、静态图解和动态实现沿用 `arts/backgrounds/NN/`、`arts/items/NN/`、`arts/static/NN/`、`arts/actions/NN/`。跨章共用新资源可放对应shared目录，注册章节用途；已有资源引用原路径及哈希，不为“移到后章”破坏旧引用、重复生成或悄悄修改原图。
- 动态目录按需包含布局、时间轴、播放器、`captions/`、`exports/`、`provenance/<stage>/`；本项目不在 `.tmp` 新建制作副本，原始输出与采用／淘汰关系明确。

## 衔接与完成

每次改镜头都检查入点、出点及邻镜；章末输出下章可接收状态。用 [边界契约模板](assets/boundary-contract.json) 保存实际状态、来源和候选接法，`null` 表示未定，不冒充已验收。

按阶段验证文字对应、素材尺寸／alpha／引用、时间连续、状态语义、关键动作及切点。视频另查实测时长、帧数、尺寸、帧率、音轨、编码后抽帧及全程解码。两章均可播时检查切点前后短预览，再标记衔接通过；邻章未制作时只记录候选。

同步 `PROJECT_STATE`、`HANDOFF`、`GENERATION_LOG` 和本章入口，记录实际模型或“无模型调用”、输入输出哈希、采用修改、命令与验证范围。不要把本技能编写、状态采样或单章导出记成后续章节已制作。

调用示例：

> 使用 $chapter-video-production 继续02，先读取01终态与02口播，细化镜头并准备美术，保持无配音；完成可播放预览后检查01→02衔接。

> 使用 $chapter-video-production 继续03–06中已授权的下一章，从现有产物恢复，按章节制作单推进并更新相邻章边界契约。
